# Diabetes Risk Prediction

A deep learning system for diabetes risk assessment, delivered as a full-stack web application. The model predicts a user's diabetes risk from routine health indicators, then follows up with AI-generated dietary guidance, high-risk email alerts, and daily meal/exercise reminders.

Diabetes affects an estimated 589 million adults worldwide (IDF Diabetes Atlas, 11th edition, 2024), and early risk identification is one of the most effective levers for prevention and timely intervention. This project explores that problem end-to-end: from data cleaning and class-imbalance handling, through model training and threshold tuning, to a deployed application a user can actually interact with.

Originally built as a 4th-semester AI course project by a team of four.

## Overview

- **Model**: a feedforward neural network (TensorFlow/Keras) trained on the [Diabetes Prediction Dataset](https://www.kaggle.com/datasets/iammustafatz/diabetes-prediction-dataset) (~100k records), using class-weighted loss to address the dataset's ~8:1 class imbalance
- **Backend**: a Flask REST API serving predictions, authentication, and account management
- **AI-generated advice**: Google Gemini produces personalized dietary/lifestyle recommendations based on each prediction
- **Automated follow-up**: high-risk assessments trigger an email alert; users can opt into daily meal and exercise reminder emails
- **Frontend**: an HTML/CSS/JS interface for running assessments, viewing an analytics dashboard, and managing account data (including full account deletion)

## Methodology

1. **Data cleaning** (`preprocessing.py`): duplicate removal, outlier capping (BMI, blood glucose), standardization of categorical labels
2. **Preprocessing pipeline**: `StandardScaler` for numeric features, one-hot encoding for categorical features, fit with scikit-learn's `ColumnTransformer` and persisted with `joblib` so training-time and inference-time preprocessing stay identical
3. **Class imbalance**: trained primarily with class-weighted loss; a SMOTE-balanced dataset variant is also produced for comparison
4. **Model architecture** (`model.py`): a 3-hidden-layer dense network (128 → 64 → 32 units) with batch normalization and dropout, trained with early stopping on validation AUC
5. **Threshold tuning**: rather than using the default 0.5 cutoff, the decision threshold is tuned on the F1 score across a range of candidate values, since the clinically relevant trade-off is between false negatives (missed risk) and false positives (unnecessary alerts)

## Results

- **ROC-AUC: 0.928** on the held-out test set
- At the deployed decision threshold, the model achieves a recall of ~65% on the diabetic class (i.e., correctly flags roughly two-thirds of true diabetic cases), reflecting a deliberate bias toward sensitivity given the cost of a missed high-risk case

Full training curves, ROC curve, and confusion matrix are generated by `model.py` and saved to `model_evaluation.png`.

## Getting Started

### Prerequisites
- Python 3.10–3.11 (tested with 3.11; check TensorFlow's [install guide](https://www.tensorflow.org/install/pip) for current version support)
- A Gmail account with an [App Password](https://myaccount.google.com/apppasswords) (for sending emails)
- A [Google Gemini API key](https://aistudio.google.com/apikey)

### Installation

```bash
git clone https://github.com/<your-username>/diabetes-risk-prediction.git
cd diabetes-risk-prediction

python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # macOS/Linux

pip install -r requirements.txt
```

### Configuration

```bash
cp .env.example .env
```

Fill in `SECRET_KEY` (generate with `python -c "import secrets; print(secrets.token_hex(32))"`), `GEMINI_API_KEY`, `EMAIL_SENDER`, and `EMAIL_PASSWORD`.

### Running

The trained model (`diabetes_model.keras`) and fitted preprocessor (`preprocessor.pkl`) are included, so the app runs directly:

```bash
python app.py
```

Visit `http://127.0.0.1:5000`.

To retrain the model from scratch:

```bash
python preprocessing.py   # cleans data, fits the preprocessor, saves train/test splits
python model.py            # trains the network, tunes the decision threshold, saves the model
```

## API Overview

| Endpoint | Method | Description |
|---|---|---|
| `/api/signup`, `/api/login` | POST | Authentication |
| `/api/predict` | POST | Run a risk assessment |
| `/api/dietary` | POST | Ask the AI a dietary question |
| `/api/history`, `/api/statistics` | GET | Retrieve a user's past assessments |
| `/api/export/csv`, `/api/export/pdf` | GET | Download assessment history |
| `/api/reminder/settings` | GET/POST | Configure meal/exercise reminders |
| `/api/account` | DELETE | Permanently delete account and associated data |

All endpoints except `/api/signup`, `/api/login`, and `/api/health` require a `Bearer` JWT token.

## Limitations & Future Work

- The model is trained on a single public dataset; performance on other populations or clinical settings is untested and would need external validation
- Feature set is limited to what the dataset provides (age, BMI, glucose, hypertension, heart disease, smoking history) — richer clinical features (e.g., HbA1c, family history) would likely improve performance
- The decision threshold is tuned for F1 on this dataset's class balance; a deployed clinical tool would need threshold selection driven by a formal cost analysis of false negatives vs. false positives
- Planned: containerized deployment, automated test coverage, and a comparison against gradient-boosted tree baselines (XGBoost/LightGBM)
